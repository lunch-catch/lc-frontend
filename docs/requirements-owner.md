# 런치캐치 — 점주 기능 요구사항 명세서

> FE-점주 담당: 이규태
> 기준 문서: 요구사항 명세서 V47 (2026-10-01 반영)

## 계정 관리

### 점주 회원가입
- **우선순위:** 필수
- **설명:** 점주가 Email과 비밀번호를 등록하여 로그인에 사용할 자체 계정을 생성한다
- **입력:** Email, 비밀번호
- **선택:** -
- **상세:**
  - 회원가입 정보를 입력받아 이메일 중복 여부를 확인한다. 비밀번호와 비밀번호 확인은 프론트에서 일치 여부를 확인한다. 비밀번호는 BCrypt로 해싱하여 저장한다. 계정 권한은 클라이언트가 아니라 서버에서 OWNER로 설정한다. 회원가입 완료 시 점주 상태를 ONBOARDING으로 저장한다
  - 비밀번호는 8자 이상 20자 미만(8~19자)이어야 하며, 문자 종류(영문, 숫자, 특수문자) 조합은 제한하지 않는다
- **예외:** 이메일 중복, 필수값 누락, 입력 형식 오류 또는 비밀번호 길이 규칙 위반이 있으면 가입 불가. 비밀번호와 비밀번호 확인의 일치 여부는 프론트에서 검증

### 점주 로그인
- **우선순위:** 필수
- **설명:** 점주가 점주 자체 계정(Email, 비밀번호)으로 로그인한다
- **입력:** Email, 비밀번호, 튜토리얼 확인 여부(tutorialViewed, 응답)
- **선택:** -
- **상세:**
  - 점주가 입력한 비밀번호와 저장된 BCrypt 해시를 비교한다. 계정이 존재하지 않는 경우에도 Dummy BCrypt Hash와 비교하여 계정 존재 여부가 드러나지 않게 한다.
  - 점주 상태가 ONBOARDING 또는 ACTIVE인 경우만 로그인 가능.
  - 인증 성공 시 최근 로그인 시각을 갱신하고, Access Token(JWT)과 Refresh Token(Opaque Token)을 HttpOnly 쿠키로 전달하며, 토큰 정책은 공통 "토큰 인증 및 역할 기반 접근 제어" 행을 따른다.
  - ONBOARDING 상태에서는 입점 등록에 필요한 API만 이용할 수 있고, ACTIVE 전환 후 전체 점주용 서비스 API를 이용할 수 있다.
  - 튜토리얼 확인 여부(tutorialViewed)는 기본값 false로 저장한다. ACTIVE 상태의 점주가 로그인하면 해당 값을 함께 반환하며, false이면 프론트에서 최초 튜토리얼을 노출한다. 점주가 튜토리얼을 완료하면 true로 변경하고 이후 로그인 시에는 다시 노출하지 않는다.
- **예외:** 이메일이 존재하지 않거나 비밀번호가 일치하지 않는 등 인증에 실패하면 구체적인 실패 사유를 노출하지 않고 공통 메시지로 처리. 점주 상태가 SUSPENDED 또는 WITHDRAWN이면 로그인 불가

### 점주 토큰 재발급
- **우선순위:** 필수
- **설명:** 점주가 로그인 상태를 유지하기 위해 세션을 갱신한다
- **입력:** Refresh Token
- **선택:** -
- **상세:**
  - HttpOnly 쿠키의 Refresh Token을 검증하고, 저장된 Refresh Token Hash 및 만료 정보를 확인한 뒤 Access Token을 새로 발급한다. 기존 Refresh Token은 폐기한 뒤 새 Refresh Token으로 교체한다(Rotation)
- **예외:** Refresh Token이 없거나 유효하지 않거나 만료된 경우 재발급 불가. Refresh Token에 연결된 점주 ID와 권한 정보를 확인하여 실제 점주 계정과 일치하지 않거나 재발급이 불가능한 계정 상태이면 재발급 불가

### 점주 로그아웃
- **우선순위:** 필수
- **설명:** 점주가 로그인 상태를 종료하고 이후 기존 세션으로는 접근할 수 없게 한다
- **입력:** Access Token
- **선택:** -
- **상세:**
  - Access Token을 검증하여 로그아웃을 요청한 점주를 식별한 뒤, 사용 중인 Refresh Token을 폐기하고, 인메모리 캐시에 로그아웃 시점을 cutoff로 저장하여 해당 시점 이전에 발급된 Access Token을 차단한다.
  - 이후 브라우저에 Access Token과 Refresh Token 쿠키 삭제를 지시한다
- **예외:** Access Token이 없거나 유효하지 않으면 로그아웃 요청 거부. 관계형 DB 또는 인메모리 캐시 중 한 곳이라도 Refresh Token 폐기에 실패하거나 Access Token cutoff 저장에 실패하면 로그아웃은 실패로 처리

## 입점 신청

### 점주 약관 동의
- **우선순위:** 필수
- **설명:** 회원가입을 완료한 점주가 서비스 이용에 필요한 점주 약관에 동의한다
- **입력:** 필수 약관 동의 여부, 약관 버전
- **선택:** 선택 약관 동의 여부
- **상세:**
  - 필수 약관에 모두 동의해야 다음 단계인 가게 기본 정보 입력을 진행할 수 있으며, 동의 시점과 약관 버전을 저장한다.
- **예외:** 필수 약관에 동의하지 않으면 가게 기본 정보 입력 단계로 진행 불가. 이미 동의한 동일 버전의 약관은 중복 동의 불가

### 가게 기본 정보 등록
- **우선순위:** 필수
- **설명:** 점주가 입점할 가게의 기본 정보를 등록하고, 상호명을 이용해 카카오맵에서 카카오 장소 ID, 도로명 주소, 전화번호, 위치 정보를 받아온다
- **입력:** 상호명, 업종, 대표자 성명
- **선택:** -
- **상세:**
  - 상호명, 업종, 대표자 성명을 입력한다. 입력한 상호명을 검색어(query)로 카카오맵 장소 검색을 수행하고, 검색 결과에서 본인 가게를 선택한다. 선택한 장소의 카카오 장소 ID, 도로명 주소, 전화번호, 위치(위도/경도)를 가져와 가게 정보로 사용한다.
  - 이 단계에서도 점주 상태는 ONBOARDING을 유지하며, 점주 계정 1개에 가게 1개만 등록 가능하다.
  - 가게 기본 정보 최초 저장 시 가게 ID를 생성하며, 이후 등록 단계에서 해당 가게 ID를 사용한다.
- **예외:** 필수 기본 정보가 누락되면 등록 불가. 카카오맵 장소 검색 결과가 없으면 빈 검색 결과 반환.

### 사업자등록정보 입력 및 Mock 검증
- **우선순위:** 필수
- **설명:** 점주가 사업자등록번호를 입력하고 내부 Mock 방식으로 유효 여부를 검증한다
- **입력:** 사업자등록번호(하이픈 없는 숫자 10자리)
- **선택:** -
- **상세:**
  - 가게 기본 정보 등록 후 사업자등록번호를 입력한다. 하이픈 없는 숫자 10자리 형식을 확인한 뒤 내부 Mock 검증을 수행한다. 검증에 성공하면 검증 성공 시각을 함께 저장한 뒤 다음 단계인 영업시간 등록으로 진행하고, 실패하면 사업자등록번호를 수정하여 다시 검증한다.
- **예외:** 숫자 10자리 형식이 아니면 Mock 검증 불가. Mock 검증에 실패하면 영업시간 등록 단계로 진행 불가

### 영업신고증 업로드
- **우선순위:** 권장
- **설명:** 점주가 본인 가게의 영업신고증 파일을 업로드한다
- **입력:** 가게 ID, 영업신고증 파일
- **선택:** -
- **상세:**
  - 점주가 본인 가게의 영업신고증 파일을 선택적으로 등록한다. 파일은 객체 스토리지의 사전 서명 URL로 클라이언트가 직접 업로드하고, 서버는 객체 존재 확인 API로 실제 업로드 여부를 확인한 뒤 파일 메타데이터를 저장한다.
  - 현재 필수 입점 등록 흐름에는 포함하지 않으며, 영업신고증을 등록하지 않아도 가게 위치, 영업시간, 가게 이미지, 가게 대표 메뉴 등록 및 가게 등록 완료와 ACTIVE 전환을 진행할 수 있다.
- **예외:** 파일 크기가 10MB를 초과하거나 허용 확장자(jpg, png)가 아닌 파일은 업로드 거부. 본인 가게가 아닌 경우 업로드 불가. 사전 서명 URL 발급 후 실제 객체 업로드가 확인되지 않으면 등록 처리 불가

### 입점 등록 진행 상태 조회
- **우선순위:** 필수
- **설명:** 점주가 자신의 입점 등록 진행 상태와 가게 최종 등록 가능 여부를 조회한다
- **입력:** 가게 ID
- **선택:** -
- **상세:**
  - ONBOARDING 상태에서도 진행 상태를 조회할 수 있다. 약관 동의, 가게 기본 정보 등록, 카카오맵 장소 선택, 사업자등록번호 Mock 검증, 영업시간 등록, 가게 대표 이미지 등록, 대표 메뉴 3개와 각 메뉴별 이미지 1개 및 필수 메뉴 정보(메뉴명, 메뉴 가격) 등록 여부를 기준으로 진행 상태를 판단한다. 가게 내부 이미지와 메뉴 상세설명은 선택 항목이므로 완료 여부에 영향을 주지 않는다. 모든 필수 등록 단계를 완료한 뒤, 가게 최종 등록을 하면 입점 등록 진행 완료로 보여준다.
- **예외:** 본인 가게의 진행 상태만 조회 가능. 미완료된 필수 항목이 있으면 해당 항목을 안내

## 가게 등록

### 영업시간 등록/수정
- **우선순위:** 필수
- **설명:** 점주가 사업자등록번호 Mock 검사를 완료한 뒤 가게의 영업시간을 등록하거나 수정한다
- **입력:** 가게 ID, 요일, 영업 시작 시각, 영업 종료 시각, 휴무 여부
- **선택:** 브레이크 시작 시각, 브레이크 종료 시각, 라스트오더 시각
- **상세:**
  - 사업자등록번호 Mock 검사를 통과한 ONBOARDING 상태의 점주가 영업시간을 등록한다. 저장된 정보는 재로그인 후에도 유지되며 이 단계에서도 ONBOARDING 상태를 유지한다.
- **예외:** 같은 가게의 동일 요일은 중복 등록 불가. 영업일의 시작/종료 시각이 누락되거나, 휴무일에 시작/종료 시각이 입력된 경우 등록 불가. 브레이크 시작/종료 시각 중 하나만 입력된 경우 등록 불가. 필수 영업시간 정보 미등록 시, 다음 단계로 진행 불가

### 가게 이미지 및 대표 메뉴 등록/수정
- **우선순위:** 필수
- **설명:** 점주가 가게 대표 이미지와 가게 내부 이미지, 대표 메뉴 이미지 및 메뉴 정보를 등록하거나 수정한다
- **입력:** 가게 ID, 가게 로고 이미지 파일(1개), 대표 메뉴 이미지 파일(3개), 메뉴명, 메뉴 가격
- **선택:** 가게 인테리어 이미지 파일(0~3개), 메뉴 상세설명
- **상세:**
  - 가게 대표 이미지(가게 로고 이미지)는 필수로 1개를 등록하고, 가게 내부 이미지(가게 인테리어 이미지)는 최대 3개까지 선택적으로 등록한다. 대표 메뉴는 3개를 등록하며, 각 대표 메뉴마다 메뉴 이미지 1개, 메뉴명, 메뉴 가격을 필수로 등록하고, 메뉴 상세설명은 선택적으로 입력한다. 등록된 가게 관련 이미지와 대표 메뉴 정보는 수정할 수 있다. 이미지 파일은 객체 스토리지의 사전 서명 URL로 직접 업로드하고 서버가 객체 존재 확인 API로 실제 업로드 여부를 확인한다. 저장된 가게와 메뉴의 정보 및 이미지는 재로그인 후에도 유지된다.
  - 가게 최종 등록 전까지 점주 상태는 ONBOARDING을 유지한다.
- **예외:** 파일 크기가 10MB를 초과하거나 허용 확장자(jpg, png)가 아닌 파일은 업로드 거부. 본인 가게가 아니면 등록/수정 불가. 필수 항목(가게 로고 이미지 파일 1개, 대표 메뉴 이미지 파일 3개, 메뉴명, 메뉴 가격) 중 하나라도 누락되면 가게 최종 등록 불가

### 가게 최종 등록
- **우선순위:** 필수
- **설명:** 점주가 모든 필수 가게 등록 단계를 완료한 뒤 가게 등록을 최종 완료하고 점주 계정을 활성화한다
- **입력:** 가게 ID
- **선택:** -
- **상세:**
  - 필수 약관 동의, 가게 기본 정보 등록, 카카오맵 장소 선택, 사업자등록번호 Mock 검증, 영업시간 등록, 가게 대표 이미지 등록, 대표 메뉴 3개와 각 메뉴별 이미지 1개 및 필수 메뉴 정보(메뉴명, 메뉴 가격) 등록이 모두 완료되면 가게 최종 등록으로 처리하고 점주 상태를 ONBOARDING에서 ACTIVE로 전환한다. 가게 내부 이미지와 메뉴 상세설명은 선택 항목이며 최종 등록 조건에 포함하지 않는다. ACTIVE 전환 후 캠페인 등록, 가게 관리, 대시보드 등 전체 점주 서비스 API를 이용할 수 있다. 별도의 관리자 승인/반려 단계는 사용하지 않는다.
- **예외:** 필수 등록 단계 중 하나라도 완료되지 않으면 가게 최종 등록 및 ACTIVE 전환 불가. 활성화 처리 실패 시 ONBOARDING 상태 유지

## 캠페인 관리

### 캠페인 생성 (쿠폰 조건 입력)
- **우선순위:** 필수
- **설명:** 점주가 캠페인 등록의 1단계로 쿠폰 조건을 입력한다
- **입력:** 할인 대상(전체/특정 메뉴), 할인 유형(퍼센트/금액), 할인 값, 선착순 쿠폰 발급 수량, 사용 가능 시간(시작, 종료)
- **선택:** 메뉴 ID, 최소 주문 금액, 유의사항
- **상세:**
  - 등록 순서: 쿠폰 조건 -> 포스터 -> 노출 대상 -> 하루 예산과 집행 기간 -> 확인. 각 단계는 DRAFT로 저장되어 이어서 작성 가능.
  - 사용 가능 시간은 플랫폼 허용 범위 11:30~15:00 안에서 30분 단위로 시작과 종료를 선택(최소 1시간, 연속 구간 1개, 기본값 전체).
  - 선착순 오픈 시각(11:00)은 플랫폼 고정이라 입력하지 않고 안내만 표시. 점주 상태 ACTIVE인 경우에만 진입 가능
- **예외:** 진입 조건(점주 ACTIVE)을 충족하지 않은 점주는 캠페인 생성 진입 불가. 할인율 퍼센트가 100%를 초과하거나, 선착순 쿠폰 발급 수량이 0 이하이거나, 쿠폰 사용 시간이 1시간 미만이거나 허용 범위(11:30~15:00) 밖이면 저장 불가

### 노출 대상 설정 (등록 3단계)
- **우선순위:** 필수
- **설명:** 점주가 캠페인이 노출될 사용자 범위(반경, 성별, 연령대)를 설정한다
- **입력:** 점주 반경(500m / 1km / 2km / 3km), 성별(전체/남/여), 연령대(20대/30대/40대/50대 이상, 다중)
- **선택:** 없음
- **상세:**
  - 기본값은 1km, 전체, 전체. 시간대는 점심 고정으로 선택 없음. 모든 사용자가 성별과 연령대를 입력하므로 타겟 일치 여부만 판정한다
- **예외:** 반경 선택지 외의 값은 거부

### 하루 예산과 집행 기간 설정/변경 (등록 4단계)
- **우선순위:** 필수
- **설명:** 점주가 캠페인의 하루 최대 소진 포인트와 집행 기간을 설정하고 예상 노출을 확인한다. 활성화 이후에도 하루 예산을 바꿀 수 있으며 다음 날 00:00부터 적용된다
- **입력:** 하루 예산(포인트), 집행 시작일, 집행 종료일
- **선택:** 없음
- **상세:**
  - 입력 즉시 최대 노출 수(하루 예산 / 노출 단가)와 예상 노출 범위(반경 내 최근 7일 점심 접속 사용자 수, 경쟁 캠페인 수 기반)를 "예상"으로 표시하고, 최소 보장이 없음을 함께 표시.
  - 추천 하루 예산 = 점주 반경 내 최근 7일 점심 접속 사용자 중 이 캠페인의 노출 대상 조건(성별, 연령대)에 맞는 인원(중복 제거) x 노출 횟수 상한 2회 x 노출 단가. 반경 내 7일치 데이터가 없으면 부트스트랩 하루 예산을 제시한다. 노출 단가, 최소 하루 예산, 부트스트랩 하루 예산은 운영의 플랫폼 설정값(관리자 "플랫폼 설정값 관리")에서 읽는다.
  - 추천에 쓰는 인원은 광고 서빙이 매일 00:00 배치 (10)단계에서 가게마다 점주 반경 4단계 x 성별 x 연령대 칸으로 세어 캠페인에 넘기고, 캠페인은 넘겨받은 값으로 추천값을 계산한다. 캠페인은 광고 서빙을 조회하지 않는다. 광고 서빙이 이미 캠페인을 조회하고 있어 반대 방향을 열면 도메인 간 순환이 생긴다(공통 "하루 시간표 스케줄러"). 추천값은 전날 00:00 기준이며, (10)단계가 실패하면 그 전날 값을 쓴다. 예상 노출 범위의 사용자 수도 같은 값을 쓴다.
  - 노출 횟수 상한이 (사용자, 캠페인) 조합당 하루 2회이므로 그 인원이 하루에 받을 수 있는 노출은 인원 x 2가 상한이다. 그보다 큰 하루 예산은 수요가 없어 구조적으로 다 쓸 수 없다. 집행 기간은 3일 이상 권장(신규 우선 노출 기간과 일치).
  - 하루 예산은 매일 00:00 초기화, 미소진분 이월 없음.
  - 점주가 설정한 하루 예산과 그날 실제로 적용되는 하루 예산은 다를 수 있다. 00:00에 잔액이 설정값보다 적으면 그날은 잔액까지만 예약해 집행한다(공통 "하루 예산 배분 및 예산 소진 진행률 계산").
  - 활성화 이후에도 하루 예산을 바꿀 수 있다. 바꾼 값은 다음 날 00:00부터 적용되고 그날 서빙에는 영향을 주지 않는다. 노출 단가와 같은 방식이다(관리자 "플랫폼 설정값 관리"). 캠페인이 바뀐 값을 다음 영업일 적용 예약 값으로 들고 있다가 00:00 배치 (3)단계에서 적용한다(공통 "하루 시간표 스케줄러").
  - 당일 적용으로 두지 않는 이유는 하루 예산이 예산 소진 진행률의 분모이기 때문이다(비즈니스 규칙 "예산 소진 진행률"). 서빙 중에 분모가 바뀌면 진행률이 점프해 배분 슬롯 순서가 흔들린다. 11:30에 하루 예산 10,000을 30,000으로 올리면 진행률이 0.40에서 0.13으로 떨어져 그 캠페인이 배분 슬롯을 계속 먼저 받고, 3,000으로 내리면 1.33이 되어 상한 1.2를 넘겨 즉시 후보에서 빠진다. 앞엣것은 "예산 크기는 노출 총량만 정하고 순서에 영향이 없어야 한다"는 비즈니스 규칙 "예산 크기와 노출량"과 "공정성 판단 기준"을 깨고, 11:00 직전에 예산을 올리는 것이 순위 조작 수단이 된다
- **예외:** 하루 예산이 최소 하루 예산(운영 설정값, 관리자 "플랫폼 설정값 관리") 미만이거나, 집행 기간이 1일 미만이거나, 종료일이 시작일 이전이면 저장 불가. 집행 시작일은 등록일 다음 날 이후만 선택 가능(등록 마감 D-1 23:59). 잔액 부족은 저장과 변경을 막지 않는다. 화면은 정산의 잔액 조회를 따로 불러 부족분과 충전 버튼을 표시하고, 실제 집행은 00:00 예약에서 잔액까지로 제한된다(공통 "하루 예산 배분 및 예산 소진 진행률 계산"). 집행 기간은 활성화 이후 바꿀 수 없다

### 캠페인(쿠폰) 조회
- **우선순위:** 필수
- **설명:** 점주가 자신이 등록한 캠페인(쿠폰)의 목록과 상세 정보를 조회한다
- **입력:** 캠페인 ID, 캠페인 상태, 할인 대상, 할인 유형, 할인 값, 선착순 쿠폰 발급 수량, 사용 가능 시간, 하루 예산, 집행 기간, 캠페인 등록시각
- **선택:** 없음
- **상세:**
  - 점주 본인이 등록한 캠페인만 조회 가능. 캠페인 목록에서 상태, 등록일, 마감일을 확인. 특정 캠페인 선택 시 해당 캠페인의 상세 정보 조회 가능.
- **예외:** 점주는 다른 점주의 캠페인을 조회할 수 없음. 조회 대상 캠페인이 없으면 빈 목록 반환

### 캠페인 활성화 (1건 제한)
- **우선순위:** 필수
- **설명:** 점주가 캠페인 활성화를 요청한다. 캠페인은 자동 검수를 거쳐 SCHEDULED가 되고, 집행 시작일 00:00에 시스템이 ACTIVE로 전환한다. 한 가게에서 동시에 1건만 활성 상태를 유지한다
- **입력:** 캠페인 ID
- **선택:** 없음
- **상세:**
  - 활성화 요청 시 (1) 포스터 존재 확인 후 (2) 자동 검수. 잔액은 서버에서 검사하지 않는다. 화면이 정산의 잔액 조회를 따로 불러 잔액이 하루 예산보다 적으면 부족분과 충전 버튼을 표시한다. 잔액이 모자란 채 활성화되면 첫 서빙일 00:00 예약에서 잔액 부족으로 PAUSED(NO_POINTS)가 된다("잔액 부족 시 캠페인 게재 중단"). 캠페인은 잔액을 보관하지 않으므로 정산을 조회하지 않는다. 캠페인이 정산을 조회하면 정산이 이미 캠페인을 조회하고 있어 도메인 간 순환이 생긴다. 자동 검수 PASS면 SCHEDULED, FAIL이면 DRAFT 유지와 사유 표시.
  - D일 서빙은 D-1일 23:59까지 SCHEDULED가 된 캠페인만 대상이며 D일 00:00 스케줄러가 일괄 ACTIVE로 전환한다. 당일 등록의 가장 빠른 서빙은 다음 날.
  - ACTIVE 전환 시 기존 ACTIVE 캠페인은 ENDED 처리하며, (가게 ID, 활성 여부) 조합의 UNIQUE 제약으로 한 가게에 활성 캠페인이 2건 존재하는 상태를 DB 수준에서 차단한다
- **예외:** 캠페인에 포스터가 없으면 활성화 요청 불가. 잔액 부족은 활성화를 막지 않는다(화면 안내만). PAUSED(ADMIN) 상태 캠페인은 점주가 재개 불가

### 캠페인 수동 중단/재개
- **우선순위:** 필수
- **설명:** 점주가 활성 캠페인을 직접 중단하고 재개한다
- **입력:** 캠페인 ID, 처리(중단/재개)
- **선택:** 없음
- **상세:**
  - 중단 시 PAUSED(사유 OWNER), 다음 피드 요청부터 미노출. 당일 이미 소진된 포인트는 환급하지 않음. 이미 내려간 카드에서 중단 이후 도착한 노출은 무효가 아니라 유효 노출이며, 캠페인이 과금 판정에서 NOT_BILLED_PAUSED를 돌려줘 과금하지 않는다(공통 "노출 차감 및 원장 기록"). 중단과 재개는 캠페인이 상태 변경 이벤트를 발행해 알리고, 광고 서빙이 받아 그날 후보 스냅샷에 바로 반영한다(공통 "캠페인 상태 전이"). 점주가 재개하면 그날 남은 예약액(그날 적용 하루 예산 - 당일 소진)을 남은 서빙 시간에 나누어 시간대별 목표 소진을 다시 계산하고 노출 속도를 조절한다. 재개는 잔액을 다시 읽지 않는다. 그날 쓸 포인트는 00:00에 이미 예약돼 있다(공통 "하루 예산 배분 및 예산 소진 진행률 계산"). 집행 기간이 지나면 재개 불가(ENDED)
- **예외:** PAUSED(ADMIN) 상태 캠페인은 점주가 재개 불가. ENDED 상태 캠페인은 재개 불가. 그날 남은 예약액이 노출 단가보다 적으면 그날 더 노출할 수 없으므로 재개를 거부한다. PAUSED(NO_POINTS)는 충전으로만 재개된다("포인트 결제", "잔액 부족 시 캠페인 게재 중단")

## 포인트

### 포인트 결제
- **우선순위:** 필수
- **설명:** 점주가 광고 노출에 필요한 포인트를 선불 결제로 충전한다
- **입력:** 점주 ID, 충전 상품(금액), 결제대행사 결제 승인 ID
- **선택:** -
- **상세:**
  - 캠페인 확인 화면에서 필요 포인트(하루 예산 x 집행 일수)와 잔액을 비교해 부족분을 표시하고 충전 화면으로 연결한다.
  - 결제는 결제대행사를 통해 처리하며 본 프로젝트는 테스트 결제(미결정 사항 참조). 승인 콜백 수신 시 1원 = 1포인트로 즉시 충전하고 원장에 CHARGE를 기록한다.
  - (노출 1회당 몇 포인트가 차감인지 결정해야한다.)
  - (결제 ID, 원장 유형) UNIQUE 제약으로 멱등 처리하여 같은 결제가 두 번 반영되지 않는다. 충전 완료 시 그 점주에게 집행 기간 안의 PAUSED(NO_POINTS) 캠페인이 있으면, 정산이 그날 예약을 다시 잡는다(예약액 = min(설정 하루 예산, 기존 예약액 + 잔액), 늘어난 만큼 RESERVE 기록). 새 예약액을 캠페인에 넘기면 캠페인이 재개를 판정한다("잔액 부족 시 캠페인 게재 중단"). 서빙 시간대가 지났으면 다시 잡지 않고 다음 00:00 예약을 기다린다. 그날 예약은 13:30에 해제된다.
  - 외부 API 장애에 대비해 타임아웃과 서킷브레이커를 적용하고, UNKNOWN 상태는 재조회로 확정한다
- **예외:** 결제가 실패하거나 취소되면 포인트 충전 없음. 같은 결제 승인 통지가 중복 수신되어도 충전은 1회만 반영. 충전 금액이 최소 충전 금액 미만이면 결제 불가

### 잔액 및 내역 조회
- **우선순위:** 필수
- **설명:** 점주가 잔액과 충전/차감 내역을 조회한다
- **입력:** 점주 ID
- **선택:** 캠페인 ID, 일자
- **상세:**
  - 표시 잔액은 원장 합계다. 그날 예약된 포인트 중 아직 쓰지 않은 금액(예약 중 포인트)을 잔액과 따로 표시한다. 차감 내역은 캠페인별, 일별 소진 포인트로 집계한다. 무효 노출로 차감했던 포인트를 되돌린 환급과 예약 해제는 별도 유형으로 표시
- **예외:** 원장 조회가 실패하면 잔액 대신 조회 실패 안내를 표시한다. 캐시된 잔액으로 대신 표시하지 않는다

### 잔액 부족 시 캠페인 게재 중단
- **우선순위:** 필수
- **설명:** 그날 예약한 포인트(그날 적용 하루 예산)가 노출 단가보다 적으면 시스템이 캠페인 게재를 중단한다
- **입력:** 캠페인 ID, 점주 ID, 그날 예약액, 노출 단가, 설정 하루 예산, 당일 소진
- **선택:** -
- **상세:**
  - 매일 00:00 배치에서 정산이 점주 잔액에서 그날 쓸 포인트를 예약하고(공통 "하루 예산 배분 및 예산 소진 진행률 계산") 그 예약액을 캠페인에 넘긴다. 캠페인은 넘겨받은 예약액을 그날 적용 하루 예산으로 쓰며, 그 값이 노출 단가보다 적으면 그날 한 번도 노출할 수 없으므로 잔액 부족으로 판정해 상태를 PAUSED(사유 NO_POINTS)로 바꾼다.
  - 판정 시점은 둘이다. 00:00 예약 직후와, 충전으로 예약이 다시 잡힌 직후("포인트 결제")다. 둘 다 서빙 경로 밖이다. 초당 10,000건이 지나는 차감 경로는 예약액 안에서만 차감하므로(공통 "노출 차감 및 원장 기록") 잔액을 보지 않으며 유실에 대비해 다시 알릴 필요도 없다.
  - 잔액은 정산만 가진다. 캠페인은 잔액을 보관하지 않고 그날 예약액과 당일 소진만 가진다. 상태를 바꾸는 권한은 캠페인 하나에만 있다.
  - 충전으로 예약액이 노출 단가 이상이 되면 캠페인이 ACTIVE로 되돌린다(자동 재개). 서빙 시간대가 지난 뒤의 충전은 다음 날 00:00 예약에서 반영된다
- **예외:** 집행 기간이 지난 캠페인은 충전해도 재개하지 않고 ENDED 처리. 관리자가 중단한 캠페인(PAUSED, 사유 ADMIN)은 충전으로 재개되지 않는다. 서빙 중에는 잔액 부족으로 중단되지 않는다. 그날 차감은 예약액 안에서만 일어나므로 잔액이 음수가 되지 않는다

### 포인트 환불 요청
- **우선순위:** 권장
- **설명:** 점주가 미사용 포인트의 환불을 요청한다
- **입력:** 점주 ID
- **선택:** 사유
- **상세:**
  - 잔액 전액 환불만 가능. 그날 예약된 포인트는 제외된다(관리자 "환불처리"). 요청 전 환불 정책(수수료)과 예상 환불액 표시. 관리자 승인 후 처리. 실제 환불은 mock 처리
- **예외:** 점주에게 활성 캠페인이 있으면 먼저 중단하도록 안내하고 환불 요청 거부. 대기 중인 환불 요청이 있으면 중복 요청 불가

## 포스터 관리

### 템플릿 목록 조회
- **우선순위:** 필수
- **설명:** 점주가 포스터 생성 시 고를 수 있는 게시·활성 템플릿 목록을 조회한다
- **입력:** 템플릿ID, 템플릿명, 미리보기(iframe)
- **선택:** -
- **상세:**
  - 게시되고 활성 상태인 템플릿만 대상(임시저장 중이거나 비활성인 템플릿은 제외 — 관리자용 목록과 대상이 다름)
  - 목록에서 선택해 포스터 생성으로 진행
- **예외:** 활성 템플릿이 하나도 없으면 빈 배열 응답

### 포스터 생성
- **우선순위:** 필수
- **설명:** 점주가 관리자 템플릿을 고르고 쿠폰 조건을 입력하면 시스템이 템플릿 슬롯을 채워 포스터를 만든다
- **입력:** 캠페인 ID, 템플릿 ID, 할인 내용, 기간, 가게명
- **선택:** 가게 이미지, 메뉴 이미지
- **상세:**
  - 점주가 활성 템플릿 중 하나를 고르고 쿠폰 조건(할인 내용, 기간, 가게명, 이미지)을 입력하면 해당 값이 템플릿 슬롯에 채워진다.
  - 템플릿 HTML 구조는 바뀌지 않으며 슬롯 값만 채워진다. 생성 결과는 30초 이내에 iframe 기반 미리보기로 표시한다
- **예외:** 비활성화/미게시된 템플릿으로는 포스터 생성 불가. 캠페인당 포스터는 1건만 생성되며, 이미 포스터가 있는 캠페인에 대한 생성 재요청은 수정으로 처리

### 포스터 수정
- **우선순위:** 필수
- **설명:** 점주가 버튼으로 포스터의 텍스트/이미지 내용, 색상, 크기를 직접 수정한다
- **입력:** 캠페인 ID, 포스터 ID, 수정 항목(내용/색상/크기), 변경 값
- **선택:** -
- **상세:**
  - 텍스트와 이미지 내용은 직접 입력하거나 교체한다. 색상은 색깔 버튼으로, 크기는 사전 정의된 옵션에서 선택한다. 텍스트와 이미지의 위치는 점주가 바꿀 수 없다(관리자가 템플릿 생성 시 고정).
  - 템플릿 HTML 구조는 점주가 바꿀 수 없고 슬롯 값만 바뀐다. HTML 자체의 생성과 수정은 관리자의 템플릿 관리에서만 이루어진다.
  - 수정 결과는 iframe 기반 미리보기에 즉시 반영된다
- **예외:** 색상과 크기가 각자의 허용된 값 목록 밖이면 거부. 광고 라벨 슬롯은 삭제하거나 가릴 수 없다

### 포스터 조회
- **우선순위:** 필수
- **설명:** 점주가 포스터 편집 화면에 진입하면 시스템이 최근 저장 버전과 편집 중이던 상태(슬롯 값, 미리보기)를 불러온다
- **입력:** 캠페인 ID, 포스터 ID
- **선택:** 텍스트, 이미지
- **상세:**
  - 편집 세션이 살아있으면 그 상태 그대로 복원, 세션 만료 시 마지막 저장 버전부터 재시작
- **예외:** 저장된 버전이 없는 최초 진입 시 점주가 선택한 템플릿 기본값으로 표시

### 포스터 자동 검수
- **우선순위:** 필수
- **설명:** 시스템이 활성화 요청 시 포스터 이미지와 문구를 검수 기준에 따라 자동 검증한다
- **입력:** 캠페인 ID, 포스터 ID, 검증 결과(PASS/FAIL)
- **선택:** 판정 사유
- **상세:**
  - 기준은 검수 기준 관리 행의 설정값(텍스트 비율, 해상도, 전후 비교, 제목 길이, 금지 표현).
  - 텍스트는 금지 표현 사전으로 1차 필터링하고 이미지는 이미지 자동 검수 도구로 판별한다(도구 선택은 설계). PASS면 SCHEDULED.
  - FAIL이면 사유와 함께 점주에게 수정 요청(DRAFT 유지). 외부 호출 실패나 타임아웃도 FAIL로 처리하며, 점주는 수정 후 다시 활성화를 요청한다
- **예외:** 검수 도구 장애나 타임아웃도 FAIL로 처리. 광고 라벨 슬롯이 없는 포스터는 검수 FAIL

## 쿠폰 사용 처리

### QR 스캔 사용 처리
- **우선순위:** 필수
- **설명:** 점주가 사용자의 동적 QR을 스캔하여 쿠폰을 사용 완료 상태로 변경한다
- **입력:** QR 토큰(issue_id, 만료 시각, jti, 서명), 점주 ID
- **선택:** 점주 기기 위치
- **상세:**
  - 서버가 서명, 만료(60초), jti 미사용 여부, 발급 상태, 캠페인 사용 가능 시간 안인지를 검증한 뒤 redeem 이벤트를 생성한다. 점주 기기 위치가 매장 반경 200m 이내인지 검증(권장). 처리 결과를 점주와 사용자 화면에 즉시 표시
- **예외:** QR이 만료되었거나, 이미 사용된 QR이거나, 다른 가게의 쿠폰이거나, 이미 사용 완료된 쿠폰이면 사유 코드와 함께 사용 처리 거부

- **상세:**

- **예외:** 본인 가게의 캠페인만 조회 가능하며, 다른 점주의 캠페인 이력은 조회불가. 조회 결과가 없으면 빈 목록 반환

## 리포트

### 광고주 노출 리포트
- **우선순위:** 필수
- **설명:** 점주가 캠페인별 노출과 전환 지표를 일별/주별/월별 차트로 조회한다
- **입력:** 캠페인 ID, 하루 예산, 당일/누적 소진 포인트, 예산 소진율, 적용 노출 단가, 누적 유효 노출, 그중 미과금 노출 수(사유별), 무효 노출 수(사유별, 미차감 표시), 시간대별 노출 분포, 슬롯 유형 비율, 찜/발급/사용 수, 방문당 비용
- **선택:** 반경 확장 단계별 노출 수, 미노출 사유(반경 밖, 예산 소진 진행률 초과, 노출 횟수 상한, 타겟 불일치) 집계
- **상세:**
  - 리포트 값은 관리자 정산(노출 로그와 포인트 원장을 대조해 차감액이 맞는지 확인하는 것)과 동일한 집계 로직 사용. 소진 포인트 = 노출로 차감된 포인트 - 무효 노출로 환급된 포인트.
  - 하루가 지나 수치를 확정한 뒤에 값이 바뀌면(지연 도착 이벤트 등) 바뀐 내역을 점주가 볼 수 있게 표시한다. 전환 지표가 정산에 반영되지 않음과 노출 미보장을 화면에 명시
  - 노출 수와 소진 포인트를 곱셈으로 대조할 때는 과금 노출 수를 쓴다(미과금 노출 제외)
  - 지표는 일 1회 집계 테이블에 사전 계산하고, 리포트 조회 시 집계 결과 사용
- **예외:** 일별 확정 전 당일 데이터는 리포트에 "집계 중"으로 표시
