# 런치캐치 — 관리자 기능 요구사항 명세서

> FE-관리자 담당: 고유정
> 기준 문서: 요구사항 명세서 V47 (2026-10-01 반영)

## 계정 관리

### 관리자 계정 발급(계정 등록)
- **우선순위:** 필수
- **설명:** 최고 관리자가 다른 일반 관리자 또는 최고 관리자의 계정을 신규 발급한다
- **입력:** 관리자 ID, 초기 비밀번호, 이름, 권한(ADMIN/SUPER_ADMIN)
- **선택:** -
- **상세:**
  - 인증된 관리자 중 최고 관리자(SUPER_ADMIN)만 계정을 발급할 수 있다. 최고 관리자는 항상 1명 이상 유지한다.
  - 발급할 관리자 ID의 중복 여부를 먼저 확인한 뒤, 초기 비밀번호를 BCrypt로 해싱하고 관리자 계정을 ACTIVE 상태로 저장한다.
  - BCrypt 연산은 응답 지연을 줄이기 위해 DB 트랜잭션 밖에서 수행하며, 관리자 계정 저장과 계정 생성 감사 로그는 하나의 트랜잭션으로 처리한다
- **예외:** 요청자가 최고 관리자가 아니면 계정 발급 불가(403). 관리자 ID가 중복되면 발급 불가(409). 관리자 ID, 비밀번호, 이름, 권한의 형식이 유효하지 않으면 요청 거부(400)

---

### 관리자 로그인
- **우선순위:** 필수
- **설명:** 관리자 계정(관리자 ID, 비밀번호)으로 인증하고 관리자 세션을 시작한다
- **입력:** 관리자 ID, 비밀번호
- **선택:** -
- **상세:**
  - 로그인은 기존 Access Token 없이 접근할 수 있는 관리자 기능이다.
  - loginId로 관리자 계정을 조회하며, 계정이 존재하지 않는 경우에도 Dummy BCrypt Hash와 비교하여 계정 존재 여부가 응답 시간으로 노출되지 않도록 처리한다.
  - 관리자 계정의 비밀번호 일치 여부와 ACTIVE 상태를 확인한 뒤 Access Token(JWT, 30분)과 Refresh Token(Opaque Token, 1일)을 발급한다.
  - Refresh Token은 SHA-256 해시를 관계형 DB에 백업하고 인메모리 캐시에도 저장하며, 인메모리 캐시 저장이 실패하면 DB 백업을 기준으로 로그인을 유지한다.
  - 두 토큰은 HttpOnly, SameSite=Strict 쿠키로 전달한다. 로그인 실패 횟수 기반 계정 잠금은 향후 확장
- **예외:** 관리자 ID가 존재하지 않거나, 비밀번호가 일치하지 않거나, 계정이 현재 사용 가능한 상태가 아니면 사유를 구분하지 않고 동일한 로그인 실패로 처리(401). 관계형 DB에 Refresh Token 백업 저장이 실패하면 로그인은 실패로 처리

---

### 관리자 토큰 재발급
- **우선순위:** 필수
- **설명:** 관리자가 로그인 상태를 유지하기 위해 세션을 갱신한다
- **입력:** Refresh Token
- **선택:** -
- **상세:**
  - 토큰 재발급 또한 기존 Access Token 없이 접근할 수 있는 관리자 기능이다.
  - HttpOnly 쿠키의 Refresh Token을 검증한 뒤 새 Refresh Token을 생성하고 기존 토큰을 교체한다(Rotation).
  - 인메모리 캐시의 기존 Refresh Token을 조회하여 Rotation을 수행하고, 관계형 DB에 저장된 Refresh Token 해시와 유효 상태를 확인한 뒤 CAS 방식으로 교체한다. 인메모리 캐시 조회 실패나 장애 시에는 관계형 DB의 Refresh Token 해시를 기준으로 재발급을 진행한다.
  - 재발급 성공 시 새 Access Token과 Refresh Token을 HttpOnly 쿠키로 갱신한다
- **예외:** Refresh Token이 유효하지 않거나 만료 또는 폐기된 경우 토큰 재발급 거부. 이미 교체된 Refresh Token의 재사용이 감지된 경우 재발급 거부 및 실패 감사 로그 기록

---

### 관리자 로그아웃
- **우선순위:** 필수
- **설명:** 관리자가 로그인 상태를 종료하고 이후 기존 세션으로는 접근할 수 없게 한다
- **입력:** Access Token
- **선택:** -
- **상세:**
  - DB와 인메모리 캐시에서 현재 인증된 관리자의 Refresh Token을 폐기하고, 로그아웃 시점을 Access Token 차단 기준 시각(cutoff)으로 저장하여 로그아웃 이전에 발급된 Access Token을 차단한다.
  - 로그아웃 성공 시 Access Token과 Refresh Token 쿠키를 만료시켜 브라우저에서도 삭제한다.
- **예외:** 유효한 Access Token이 없으면 로그아웃 실패

---

## 입점 관리

### 입점 신청 목록 조회
- **우선순위:** 권장
- **설명:** 관리자가 점주들의 입점 등록 진행 및 가게 최종 등록 완료 내역을 조회한다.
- **입력:** 신청 ID, 상호, 사업자등록번호, 신청일, 상태
- **선택:** 카테고리, 주소
- **상세:**
  - 관리자는 신청일, 상호, 사업자등록번호, 점주 상태와 입점 등록 항목별 진행 여부를 조회한다. 진행 여부는 별도 상태값이 아니라 실제 저장된 정보와 검증 결과를 기준으로 판단한다.
- **예외:** 입점 등록 내역이 없을 경우, 빈 목록 반환. 관리자 승인/반려 기능은 제공 대상이 아님

---

### 입점 신청 상세 조회
- **우선순위:** 권장
- **설명:** 관리자가 특정 점주의 입점 등록 진행 상태와 가게 최종 등록 완료 정보를 조회한다
- **입력:** 가게 ID 또는 점주 ID
- **선택:** -
- **상세:**
  - 관리자는 점주 약관 동의 여부, 가게 기본 정보, 사업자등록번호 Mock 검증 결과, 가게 위치, 영업시간, 가게 이미지, 가게 대표 메뉴 등록 여부, 선택 기능인 영업신고증 업로드 여부 및 가게 등록 완료 여부를 조회한다.
  - 관리자 승인/반려 단계는 없으며, 점주는 가게 최종 등록 전까지 ONBOARDING을 유지한다. 필수 등록을 모두 마치고 가게 최종 등록을 하면 점주 상태가 ACTIVE로 전환된다.
- **예외:** 관리자는 입점 상태를 변경하거나 승인/반려 불가. 필수 등록 항목이 미완료이면 점주 상태는 ONBOARDING으로 유지.

---

## 회원 관리

### 점주 목록 조회/검색
- **우선순위:** 필수
- **설명:** 관리자가 점주를 목록 조회하고 검색, 필터링하며, 가게 최종 등록 여부를 함께 조회한다
- **입력:** 회원 ID, 상호, 상태, 가입일
- **선택:** 사업자등록번호, 최근 접속일
- **상세:**
  - 필터: 상태(활성/정지/탈퇴), 가입일 범위. 페이지당 20건. 1만 건 기준 응답 1초 이내. 조회 대상은 점주 계정이며 가게 정보(상호)를 함께 표시한다 (점주 1계정 = 가게 1개)
  - 관리자는 점주 상태와 가게 최종 등록 여부를 함께 확인할 수 있다.
- **예외:** 탈퇴한 점주는 개인정보를 마스킹한 뒤 목록에 표시. 조회 대상 점주가 없으면 빈 목록 반환

---

### 사용자 목록 조회/검색
- **우선순위:** 필수
- **설명:** 관리자가 사용자를 목록 조회하고 검색, 필터링한다
- **입력:** 회원 ID, 닉네임, 상태, 가입일
- **선택:** 최근 접속일
- **상세:**
  - 필터: 상태(활성/정지/탈퇴), 가입일 범위. 페이지당 20건. 1만 건 기준 응답 1초 이내. 사용자가 로그인할 때마다 최근 접속일 컬럼을 갱신해 목록에 표시한다
- **예외:** 탈퇴한 사용자는 개인정보를 마스킹한 뒤 목록에 표시

---

### 회원 상태 변경
- **우선순위:** 권장
- **설명:** 관리자가 회원을 활성, 정지, 탈퇴 상태로 변경한다
- **입력:** 회원 ID, 변경 상태, 처리자 ID
- **선택:** 정지 사유, 정지 기간
- **상세:**
  - 관리자가 점주를 정지하면 그 점주의 활성 캠페인은 즉시 중단(PAUSED)되고, 이후 사용자가 피드를 요청할 때부터 노출되지 않는다. 정지된 사용자는 발급 및 QR 생성 불가. 변경 내역 감사 로그 기록
- **예외:** 관리자 본인 계정은 정지 또는 탈퇴 처리 불가. 발급받은 쿠폰이 있는 사용자를 탈퇴 처리하면 해당 쿠폰은 즉시 만료

---

## 캠페인 관리

### 캠페인/포스터 목록 조회
- **우선순위:** 권장
- **설명:** 관리자가 전체 캠페인과 포스터를 조회한다
- **입력:** 캠페인 ID, 가게, 상태(PAUSED 사유 포함), 집행 기간, 하루 예산, 당일/누적 소진 포인트, 누적 유효 노출
- **선택:** 슬롯 유형별 노출 수, 무효 노출 수
- **상세:**
  - 상태에 SCHEDULED 포함. 예산 소진 진행률(누적 소진 포인트 / 누적 목표 소진 포인트), 노출 대상(반경, 성별, 연령대) 컬럼 표시. 필터: 상태, 가게, 기간
- **예외:** -

## 템플릿 관리

### 템플릿 생성
- **우선순위:** 필수
- **설명:** 관리자가 자연어로 LLM에 요청하면 LLM이 새 디자인 템플릿의 HTML을 생성한다
- **입력:** 관리자 요청 문장, 생성된 HTML, 슬롯(텍스트/이미지 위치·색상·크기)
- **선택:** -
- **상세:**
  - 관리자가 "가을 신메뉴 느낌으로 만들어줘"처럼 자연어로 요청하면 LLM이 템플릿 HTML을 생성한다.
  - 색상은 사전 정의된 팔레트 값 중에서만 나오도록 강제하고, 백엔드가 팔레트에 없는 값이면 거부한다. 전체 템플릿 수는 10개로 제한. 생성 직후는 임시저장 상태이며 게시 전까지 점주에게 노출되지 않는다
  - 템플릿은 이벤트명, 할인 내용, 기간, 이미지, 광고 라벨 자리를 슬롯으로 갖는다. 저장 전 검증기를 통과해야 하며, 허용 태그와 속성만 남기고 스크립트와 외부 리소스 로딩은 제거하고 슬롯이 하나라도 빠지면 저장하지 않는다.
- **예외:** LLM 응답이 30초를 넘으면 타임아웃으로 처리하고 관리자에게 재시도를 안내. 검증기를 통과하지 못한 결과(필수 슬롯 누락)는 저장하지 않고 사유를 표시한다.

---

### 템플릿 수정
- **우선순위:** 필수
- **설명:** 관리자가 자연어로 LLM에 요청하면 LLM이 해당 템플릿의 임시저장 버전을 수정한다
- **입력:** 템플릿 ID, 관리자 요청 문장, 수정된 HTML
- **선택:** -
- **상세:**
  - "버튼 색상을 바꿔줘"처럼 요청하면 LLM이 최신 임시저장 버전을 기준으로 다시 생성한다. 수정 결과는 새 임시저장 버전으로 남고 기존 버전은 삭제되지 않는다 (템플릿 버전별 임시저장 기능과 연결)
- **예외:** LLM 응답이 30초를 넘으면 타임아웃으로 처리하고 관리자에게 재시도를 안내. 검증기를 통과하지 못한 결과(필수 슬롯 누락)는 저장하지 않고 사유를 표시한다.

---

### 템플릿 전체 목록 조회
- **우선순위:** 필수
- **설명:** 관리자가 임시저장 중이거나 게시된 템플릿 전체를 조회한다
- **입력:** 템플릿ID, 템플릿명, 상태(임시저장중/게시됨), 활성 여부, 최종 수정시각
- **선택:** 미리보기(iframe preview 화면)
- **상세:**
  - 관리자 role 전용. 상태·활성여부와 무관하게 전체 조회.
  - 정렬 기본 최신순. 필터: 상태, 활성여부. 게시된 템플릿은 확정 버전을, 임시저장중인 템플릿은 최신 임시저장 버전을 미리보기로 표시
  - 목록은 요약 정보만 담고, 각 항목 클릭 시 실제 iframe 미리보기 화면으로 이동.
- **예외:** 템플릿이 0개면 빈 배열 응답

---

### 템플릿 버전별 임시저장
- **우선순위:** 필수
- **설명:** 관리자가 LLM 생성/수정 결과를 임시저장하여 여러 버전으로 남긴다
- **입력:** 템플릿ID, 버전번호, 버전별 저장시각, 버전별 HTML
- **선택:** -
- **상세:**
  - iframe 미리보기 확인 후 "임시저장" 선택 시 새 버전으로 저장. 누르지 않으면 결과는 저장되지 않는다.
  - 버전은 게시 전까지 계속 쌓이며 임시저장된다. 버전 개수 제한은 없다.
- **예외:** 검증기를 통과하지 못한 결과(필수 슬롯 누락)는 저장하지 않고 사유를 표시한다.

---

### 템플릿 게시
- **우선순위:** 필수
- **설명:** 관리자가 임시저장 버전 중 하나를 최종 템플릿으로 확정해 게시한다
- **입력:** 템플릿ID, 게시할 버전번호, 게시 시각
- **선택:** -
- **상세:**
  - 선택한 버전의 HTML을 최종 콘텐츠로 확정한다. 게시 시점에 그 템플릿의 임시저장 버전은 게시본 포함 전부 삭제되어 되돌릴 수 없다. (성능을 고려한 삭제 방식은 추후 결정)
  - 게시된 템플릿만 활성화 대상이 될 수 있다
- **예외:** 임시저장 버전이 없으면 게시 불가. 존재하지 않는 버전번호로 게시 요청 시 거부

---

### 템플릿 활성화 관리
- **우선순위:** 필수
- **설명:** 관리자가 게시된 템플릿의 점주 노출 여부(활성화 여부)를 관리한다
- **입력:** 템플릿ID, 활성 여부, 변경시각, 변경자(관리자ID)
- **선택:** -
- **상세:**
  - 게시된 템플릿만 활성화 대상(임시저장 중인 템플릿은 활성화 불가). 점주는 활성 템플릿만 선택 가능.
- **예외:** 게시되지 않은 템플릿에 대한 활성화 요청 거부

---

## 대시보드

### 플랫폼 현황 대시보드
- **우선순위:** 필수
- **설명:** 관리자가 점주, 사용자, 플랫폼에 대한 지표를 일별/주별/월별로 조회한다
- **입력:** 기간, 유효 노출 수, 찜 수, 발급 수, 사용 수, 가입자 수, 입점 업체 수
- **선택:** 카테고리별, 지역별 분해
- **상세:**
  - 점주 지표(노출, 찜, 발급, 사용, 하루 예산 소진율 평균/표준편차, 찜률, 발급률, 사용률, 찜->발급 전환율)는 점주 대시보드에, 사용자 지표(카테고리, 지역별 노출/찜/발급/사용)와 플랫폼 지표(유효 노출 비율, 원장 불일치 건수, 충전액과 소진액, 미소진 잔액)는 관리자 대시보드에 표시한다.
  - 지표는 일 1회 배치로 집계 테이블에 사전 계산하고, 조회 API는 집계 테이블만 읽는다.
  - 배치 실행마다 (1) 집계 결과 저장 (2) 처리 건수, 소요 시간, 실패 여부를 모니터링 지표로 등록 (3) 구조화 로그 기록을 함께 수행한다.
  - 재계산은 정기 배치 후 자동 실행, 또는 관리자가 특정 날짜를 지정해 수동 재실행하는 경로로만 수행하며 집계 테이블을 직접 수정하지 않는다
- **예외:** 집계 대상 데이터가 없는 기간은 지표를 0으로 표시. 모든 지표는 이벤트 로그로부터 재계산 가능해야 함

---

## 포인트/정산 관리

### 포인트 정책 관리
- **우선순위:** 권장
- **설명:** 관리자가 충전 상품과 최소 충전 금액을 관리한다
- **입력:** 최소 충전 금액, 충전 상품 목록(금액), 변경자 ID
- **선택:** 변경 사유
- **상세:**
  - 기본값: 최소 충전 10,000원, 상품 1만/3만/5만/10만원.
  - 노출 단가, 최소 하루 예산, 부트스트랩 하루 예산은 이 기능이 아니라 운영의 플랫폼 설정값("플랫폼 설정값 관리")에서 관리한다. 캠페인(점주 "하루 예산과 집행 기간 설정/변경 (등록 4단계)" 추천과 저장 검증, 점주 "잔액 부족 시 캠페인 게재 중단" 잔액 부족 판정, 단가 스냅샷)과 광고 서빙이 이 값을 읽어야 하는데, 정산이 이미 캠페인을 조회하고 있어 캠페인이 정산을 조회하면 도메인 간 순환이 생긴다. 운영의 설정값은 모든 도메인이 읽을 수 있다(도메인 간 의존 규칙 3).
  - 잔액이 일정량 아래로 떨어지면 자동 결제하는 기능은 향후 과제
- **예외:** 최소 충전 금액이 0 이하이면 정책 저장 불가

---

### 결제내역 조회
- **우선순위:** 필수
- **설명:** 관리자가 결제(충전) 내역과 상태를 조회한다
- **입력:** 결제 ID(결제대행사 결제키), 점주 ID, 결제 금액, 충전 포인트, 결제 상태, 결제 시각
- **선택:** 실패 사유, 결제대행사 취소 ID
- **상세:**
  - 결제 상태: PENDING, SUCCESS, FAILED, CANCELED, UNKNOWN(결제대행사 응답 불명, 재조회 대상). SUCCESS로 확정된 경우에만 원장에 CHARGE를 기록한다
- **예외:** 결제 상태가 UNKNOWN인 건은 결제대행사 조회 API로 재확인한 뒤 상태를 확정

---

### 환불처리
- **우선순위:** 권장
- **설명:** 관리자가 점주의 환불 요청을 승인 또는 반려한다
- **입력:** 환불 요청 ID, 점주 ID, 요청 포인트, 처리 결과, 처리자 ID
- **선택:** 반려 사유, 결제대행사 취소 ID
- **상세:**
  - 잔액 전액 환불만 가능(부분 환불 없음). 그날 예약된 포인트는 잔액이 아니므로 환불 대상이 아니며, 그날 13:30 예약 해제(공통 "하루 시간표 스케줄러")로 잔액에 돌아온 뒤 환불할 수 있다. 승인 시 결제대행사 결제 취소 또는 계좌 환급 후 원장 REFUND 기록. 환불 정책 적용(약관에 명시한 포인트 유효기간, 환불 조건, 수수료를 따른다)
- **예외:** 점주에게 활성 캠페인이 있으면 환불 요청 자체를 거부(점주가 먼저 캠페인을 중단해야 함). 환불 후 잔액이 음수가 되는 요청은 처리 불가

---

### 포인트 변동 조회
- **우선순위:** 필수
- **설명:** 관리자가 점주별 포인트 원장 내역을 조회한다
- **입력:** 점주 ID, 원장 유형, 변동 전 잔액, 변동 금액, 변동 후 잔액, 일시
- **선택:** 캠페인 ID, serve_id, 결제대행사 거래 ID
- **상세:**
  - 기간(일/주/월), 충전액, 예약액, 소진액, 예약 해제액, 무효 환급액, 환불액, 미소진 잔액 합계(잔액 + 예약 중 포인트)
- **예외:** 원장 합계를 기준으로 표시한다. 잔액은 원장에서 계산하며 다른 저장값을 쓰지 않는다

---

### 매출 현황 조회
- **우선순위:** 필수
- **설명:** 관리자가 플랫폼의 충전, 소진, 환급, 환불, 미소진 잔액을 기간별로 조회한다
- **입력:** 기간(일/주/월), 충전액, 소진액, 무효 환급액, 환불액, 미소진 잔액 합계
- **선택:** 점주별 상위 소진 목록
- **상세:**
  - 모든 값은 포인트 원장에서 집계하며 원장 합계와 일치해야 한다. 미소진 잔액 합계는 플랫폼이 앞으로 이행해야 할 잔액이며, 잔액과 예약 중 포인트(그날 예약액 - 당일 소진)를 더한 값이다.
  - 일별 집계는 하루 1회 미리 계산하고 조회 시에는 집계 결과만 읽는다. 당일 데이터는 "집계 중"으로 표시한다
- **예외:** 집계 값과 원장 합계가 다르면 불일치 건수를 함께 표시하고 원장 합계를 기준으로 보여준다

---

### 캠페인 등록 현황 조회
- **우선순위:** 필수
- **설명:** 관리자가 전체 캠페인의 등록 현황을 조회한다
- **입력:** 캠페인ID, 점주ID, 가게, 상태, 등록시각, 집행기간, 하루예산, 소진포인트, 누적유효노출
- **선택:** 잔액
- **상세:**
  - 등록 순 정렬. 점주별 상세 지표(잔액 등)는 대시보드/포인트 변동 조회에서 별도 확인
- **예외:** 등록된 캠페인이 없으면 빈 목록 반환

---

## 설정 관리

### 플랫폼 설정값 관리
- **우선순위:** 권장
- **설명:** 관리자가 노출/공정성/관련성 관련 설정값을 화면에서 변경한다
- **입력:** 설정 키, 설정 값, 변경자 ID, 변경 일시
- **선택:** 변경 사유
- **상세:**
  - 설정 항목: 서빙 시간대(10:00~12:59), 선착순 오픈 시각(11:00), 사용 가능 시간 허용 범위(11:30~15:00)와 최소 길이(1시간), 오픈 알림 선행 시간(10분), 등록 마감(D-1 23:59), 노출 인정 시간(30분), 피드 API 사용자당 분당 요청 수(2회), 시간대 가중치(균등 34/33/33), 배분/관련성 슬롯 비율(3:7), 노출 횟수 상한(하루 2회), 관련성 가중치(45/35/20), 반경 확장 단계(1/2/3/5km), 노출 단가(10포인트, 1포인트 = 1원), 최소 하루 예산(1,000포인트), 부트스트랩 하루 예산(3,000포인트).
  - 노출 단가를 바꾸면 다음 날 00:00부터 적용되며, 캠페인이 00:00 배치 (3)단계에서 그날 단가를 읽어 캠페인별 일 단위 스냅샷으로 저장해 나중에 단가가 바뀌어도 과거 정산이 달라지지 않게 한다.
  - 변경 이력 보관
- **예외:** 시간 관련 설정값과 노출 단가의 변경은 다음 날 00:00부터 적용, 그 외 설정값은 5분 이내 반영. 노출 단가와 최소 하루 예산이 0 이하이거나 부트스트랩 하루 예산이 최소 하루 예산보다 작으면 저장 불가. 시간대 가중치의 합이 100%가 아니거나 슬롯 비율의 합이 10이 아니면 저장 불가. 설정 변경에는 ADMIN 역할과 2차 확인이 필요(선택)

---

## 부정 관리

### 무효 노출/부정 의심 조회
- **우선순위:** 필수
- **설명:** 관리자가 무효 노출 사유별 집계와 피드 요청 제한 초과 집계를 조회한다
- **입력:** 기간, 무효 사유 코드, 건수, 사용자 ID, 캠페인 ID
- **선택:** 캠페인 ID
- **상세:**
  - 사유 코드: EXPIRED_OR_UNKNOWN(serve 기록 없음: 노출 인정 시간 초과 또는 미발급), NOT_OWNER(다른 사용자의 serve_id).
  - 피드 API의 429 발생 수를 사용자별로 함께 표시. 캠페인 무효 노출 비율 20% 초과 시 경고.
  - 특정 캠페인의 노출이 소수의 사용자 계정에서만 반복되면 경고한다(경쟁 가게가 남의 예산을 고의로 소진시키는 행위로 의심). 조회 화면에서 계정 정지로 연결
- **예외:** 없음

---

### 검수 기준 관리
- **우선순위:** 권장
- **설명:** 관리자가 자동 검수에 쓰는 소재 기준을 설정하고 변경 시 점주에게 공지한다
- **입력:** 이미지 내 텍스트 비율 상한, 이미지 최소 해상도, 전후 비교 이미지 금지 여부, 카드 제목 길이 상한, 금지 표현 목록
- **선택:** 공지 문구
- **상세:**
  - 기본값: 텍스트 비율 50%, 해상도 200x200 이상, 전후 비교 금지, 제목 20자, 금지 표현(최저가, 100% 환불, 무조건 등). 변경 이력 보관. 변경 후 등록되는 캠페인부터 적용. 변경 시 점주 공지 등록
- **예외:** 검수 기준 변경은 이미 검수를 통과한 캠페인에 소급 적용하지 않음

---

## 노출 진단

### 피드 배정 진단 조회
- **우선순위:** 권장
- **설명:** 관리자가 특정 사용자의 특정 피드가 어떻게 구성되었는지, 특정 캠페인이 그 시각에 왜 노출되지 않았는지 조회한다
- **입력:** 조회 기준: 사용자 ID(또는 피드 ID)와 시각, 또는 캠페인 ID와 시각
- **선택:** 가게 ID
- **상세:**
  - 사용자 기준 조회: 그 피드 10장의 캠페인, 슬롯 유형(배분/관련성), 위치, 배정 시점 예산 소진 진행률, 관련성 점수를 표시한다.
  - 캠페인 기준 조회: 그 시각에 후보에서 제외된 사유(서빙 시간대 밖, 사용자 반경 밖, 점주 반경 밖, 성별/연령 불일치, 진행률 120% 초과, 노출 횟수 상한, 그날 이미 패스한 캠페인, 차단 가게, 수량 소진, 중단 상태)를 표시한다.
  - 두 조회 모두 당시 적용된 설정값 버전(슬롯 비율, 가중치, 노출 횟수 상한)을 함께 보여준다. 데이터는 서빙 기록과 설정값 이력에서 읽으며 기록을 바꾸지 않는다
- **예외:** 노출 인정 시간 이후에도 조회할 수 있어야 하므로 서빙 기록 보관 기간(13개월) 안의 시각만 조회 가능. 기록이 없는 시각이나 사용자를 조회하면 "기록 없음" 표시
