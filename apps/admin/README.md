# 런치캐치 관리자

런치캐치 운영자를 위한 관리자 웹 애플리케이션입니다. AI와 대화하며 광고 포스터 템플릿을 제작하고, 캠페인·회원·결제·포인트·정산 및 부정 노출을 관리합니다.

## 주요 기능

| 메뉴 | 주요 기능 | 경로 |
| --- | --- | --- |
| 대시보드 | 점주·사용자 지표, 매출·충전 및 회원·캠페인 추이, 이전 기간 비교, 정산 불일치 안내 | `/dashboard` |
| 캠페인 관리 | 캠페인 검색·필터, 상세 정보·실적·상태 이력 조회 | `/campaigns` |
| 템플릿 관리 | 이름 검색·정렬·상태 필터, 미리보기, 게시·활성 상태와 최종 수정 정보 확인 | `/templates` |
| 템플릿 편집 | AI 채팅으로 생성·수정, 요소 선택, 버전 조회·게시·재게시, 이름 변경 | `/templates/new`, `/templates/:templateId`, `/templates/drafts/:templateId/edit` |
| 포인트 / 정산 관리 | 정산 불일치 조회·종결·유형별 정정, 환불 요청, 결제 내역, 포인트 변동 내역·수동 조정, 매출 현황, 충전 정책 | `/settlements` |
| 회원 관리 | 점주·사용자 목록, 가입 정보·계정 상태 조회, 검색·필터·정렬 | `/members` |
| 부정 관리 | 무효 노출과 캠페인 경고 조회, 사유·비율·회원 집중도 확인 | `/fraud` |
| 관리자 계정 관리 | 관리자 목록 검색, 권한 조회, 계정 발급 | `/admin-accounts` |

로그인한 `ADMIN`·`SUPER_ADMIN`이 이용하며, 관리자 계정 조회·발급은 `SUPER_ADMIN` 권한이 필요합니다. 실제 접근 권한은 백엔드에서도 검증합니다.

공통으로 라이트·다크 모드, 테이블 열 표시·순서·행 밀도 설정, 반응형 가로 스크롤, 조회 오류 안내와 재시도를 지원합니다. 검색·필터·조회 기간 등은 화면별 URL 쿼리에 반영됩니다.

### 템플릿 제작 흐름

1. 템플릿을 만들거나 기존 템플릿을 열고, 채팅으로 원하는 디자인과 수정 내용을 입력합니다.
2. 포스터 미리보기 또는 HTML 코드에서 요소를 선택해 수정 대상을 지정할 수 있습니다.
3. 버전별 결과를 확인하고 게시합니다. 게시된 템플릿도 수정한 뒤 다시 게시할 수 있습니다.
4. 목록에서 활성 여부를 관리합니다. 게시된 템플릿은 비활성화할 수 있고, 삭제는 임시저장 상태에서 제공합니다.

편집기는 채팅·포스터·HTML 영역으로 구성됩니다. 경계를 드래그해 패널 너비를 조절하고, HTML 자동 줄바꿈을 켜거나 끌 수 있습니다. 답변의 Markdown을 표시하며 점진적인 텍스트 출력과 요청 중단을 지원합니다. 프론트에서 요청을 중단해도 서버의 생성 작업까지 취소되는 것을 보장하지는 않습니다.

### 정산 불일치 처리 흐름

정산 검증에서 내역을 선택하면 점주·대상 영업일, 기준 금액·실제 금액·차액과 처리 기록을 확인할 수 있습니다. **차액은 조정 금액이 아니므로 자동 입력하지 않습니다.** 실제 결제·충전·과금 기록을 확인한 뒤 아래 기준으로 처리합니다.

| 불일치 유형 | 포인트 정정 | 조정 없이 종결 |
| --- | --- | --- |
| 결제 승인액과 충전 원장 비교 | 지급·차감 가능. 서버가 결제 승인액과 실제 충전 원장으로 정확한 금액을 검증 | 잔액에 문제가 없거나 다른 조정으로 바로잡은 경우 |
| 예약액 초과 소진 | 확인된 초과 차감액 이하의 양수 지급 | 초과 차감이 정당한 과금으로 확인된 경우 |
| 캠페인 소진액과 포인트 원장 비교 | 직접 정정하지 않고 별도 초과 소진 건을 확인 | 원장·집계 캐시 차이를 확인한 뒤 종결 |

미해결 상태 태그에서 종결 확인창을 엽니다. 종결은 포인트 잔액을 변경하지 않으며, 서버가 반환한 처리자·처리 시각과 해결 방식을 상세 패널에 표시합니다. 다른 관리자가 먼저 처리한 건은 목록을 다시 조회합니다.

포인트 정정 시 대상 점주는 고정됩니다. 캠페인 초과 소진 건은 캠페인 ID와 대상 영업일도 고정되며, 결제 불일치 정정에는 캠페인 정보를 보내지 않습니다. 일반 포인트 수동 조정은 점주를 선택해 지급·차감할 수 있습니다.

## 로컬 실행

### 준비 사항

- Vite 8의 요구 버전을 충족하는 Node.js: `20.19+` 또는 `22.12+`
- 루트 `package.json`의 `packageManager`에 지정된 pnpm
- 실행 중인 런치캐치 백엔드와 로그인 가능한 관리자 계정

아래 명령은 모두 **`lc-frontend` 루트**에서 실행합니다.

### 1. 의존성 설치

```bash
corepack enable pnpm
pnpm install
```

### 2. 환경 변수 설정

`apps/admin/.env.local` 파일을 만들고 백엔드 주소를 설정합니다.

```dotenv
VITE_API_BASE_URL=http://localhost:8080
```

주소에는 `/v1/admin`을 붙이지 않습니다. 환경 변수 변경 후 개발 서버를 다시 실행합니다. `VITE_` 변수는 브라우저에 공개되므로 비밀번호·API 비밀키를 넣지 않습니다.

### 3. 관리자 앱 실행

```bash
pnpm dev:admin
```

- 접속: http://localhost:5175
- 로그인: http://localhost:5175/login
- 포트: `5175` 고정

쿠키 인증을 사용하므로 백엔드의 CORS·쿠키 설정이 프론트 주소를 허용해야 합니다. 로컬에서는 `localhost`와 `127.0.0.1`을 혼용하지 않습니다. AI 생성과 외부 모델 인증은 백엔드에서 처리합니다.

## 빌드와 배포

```bash
pnpm --filter admin build
pnpm --filter admin preview
```

빌드 결과는 `apps/admin/dist`에 생성됩니다. 배포 환경의 `VITE_API_BASE_URL`은 빌드 시 반영됩니다. 상세 경로의 직접 접근과 새로고침을 위해 `index.html` fallback이 필요하며, 현재 `apps/admin/vercel.json`에 rewrite가 설정되어 있습니다.

환경별 주소·쿠키 인증·호스팅 설정은 [배포 문서](../../docs/deployment.md)를 참고합니다.

## 테스트와 코드 검사

```bash
pnpm --filter admin typecheck
pnpm --filter admin lint
pnpm --filter admin test
```

전체 테스트는 `scripts/test-*.mjs`를 실행합니다. 인증·API 계약·조회 캐시·템플릿 선택·대화·접근성 등 회귀 검증을 포함하며, 실제 브라우저와 DB를 연결하는 E2E 테스트와는 구분합니다.

공통 UI 컴포넌트는 루트에서 `pnpm storybook`으로 확인할 수 있습니다.

## 폴더 구조

```text
apps/admin/
├── docs/                # 상태 관리·성능 문서와 README 화면 캡처
├── public/              # 파비콘·robots.txt 등 정적 자산
├── scripts/             # 회귀 테스트
└── src/
    ├── app/             # 라우터와 페이지 코드 로더
    ├── pages/           # 경로별 화면 조합
    ├── features/        # dashboard, campaign, template, billing 등 기능
    ├── api/             # API 요청·타입·응답 검증
    ├── auth/            # 인증 상태·접근 제어
    ├── hooks/           # 공통 조회·URL 필터·검색 훅
    ├── layout/          # 사이드바와 공통 레이아웃
    └── ui/              # 관리자 공통 테이블·모달·날짜 선택기
```

기능 내부 로직은 `features`에 두고 여러 화면이 공유하는 구성은 `ui`·`hooks`로 분리합니다. 앱 간 공통 디자인 컴포넌트와 유틸리티는 모노레포의 `@repo/ui`·`@repo/utils`를 사용합니다.
