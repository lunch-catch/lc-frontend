# 관리자 상태 관리와 초기 화면 규칙

관리자 앱은 React 기본 훅과 Context, 자체 인증 저장소를 사용한다. 새로운 화면은 아래 기준을 따르고, 다른 앱의 상태 관리 방식을 이 문서로 강제하지 않는다.

## 상태의 소유자

| 상태 | 관리 위치 | 사용 기준 |
| --- | --- | --- |
| 입력 중인 검색어·모달·선택 행 | 컴포넌트 `useState` | 해당 화면에서만 필요하면 전역으로 올리지 않는다. |
| 확정된 검색어·필터·정렬·페이지·조회 기간 | `useUrlFilters`, `useUrlSearch` | URL을 확정 조건의 원본으로 삼아 뒤로 가기와 공유 주소를 복원한다. |
| 로그인·권한·인증 복원 | `adminAuthStore`, `AdminAuthProvider` | `useAdminAuth`로 사용한다. 토큰을 별도 브라우저 저장소에 보관하지 않는다. |
| 일반 서버 조회 | `useApiResource`와 기능별 래퍼 | 조회 결과·로딩·오류·재시도·요청 취소를 공유한다. |
| 여러 화면이 공유하는 템플릿 목록 | `TemplateManagementProvider` | 목록·작성 화면에서 같은 목록과 갱신 동작을 공유한다. |
| 테이블 열 표시·순서 | 공통 테이블 훅과 계정별 `localStorage` | 개인 설정만 저장하며 서버 응답을 영구 저장하지 않는다. |
| 중복 제출 잠금·DOM 참조 | `useRef` | 화면에 표시할 값은 별도 상태로 관리한다. |

입력 중인 검색어와 확정된 검색 조건은 구분한다. 단, 같은 확정 조건을 URL과 로컬 상태 양쪽에서 독립적으로 수정하지 않는다. 변경 후 다시 계산할 수 있는 합계·필터 결과도 별도 상태로 중복 보관하지 않는다.

## 조회 화면의 상태

| 상태 | 판단 기준 | 표시 |
| --- | --- | --- |
| 조회 보류 | 인증 또는 필수 조건이 없거나 조건 검증에 실패 | 필수 조건 안내 또는 검증 오류. API를 호출하지 않는다. |
| 첫 조회·조건 변경 중 | 유효한 현재 조건의 결과가 아직 없음 | 테이블은 `TableLoading`, 카드는 기존 로딩 표시나 스켈레톤. |
| 조회 실패 | 현재 요청의 오류가 있음 | `TableError` 또는 `ErrorState`. 재시도 가능한 조회에만 콜백을 제공한다. |
| 빈 결과 | 성공 응답의 목록이 빈 배열 | `TableEmpty` 또는 해당 화면의 빈 상태. |
| 정상 결과 | 성공 응답의 데이터가 있음 | 현재 조건의 실제 데이터를 표시한다. |

일반 조회 화면은 **조회 보류 → 로딩 → 오류 → 빈 결과 → 데이터** 순서로 분기한다. 빈 배열은 렌더링 편의를 위한 기본값일 뿐, 요청 성공의 근거가 아니다.

### 공통 조회 훅의 계약

`useApiResource(load, query, formatError?)`는 다음 값을 반환한다.

- `enabled`: 인증된 계정과 유효한 조회 조건이 있어 요청할 수 있는지 여부.
- `loading`: 현재 계정·조건·재조회 차수에 대응하는 결과를 기다리는지 여부.
- `data`: 현재 조건의 성공 응답. 응답 전과 실패 시에는 `undefined`.
- `error`: 현재 요청의 오류 안내. 오류를 정상 데이터나 숫자 0으로 바꾸지 않는다.
- `refresh`: 현재 조건을 다시 조회한다.

`query === null`은 조회 보류이며, `query === ''`는 필터 없는 유효한 전체 조회다. 두 값을 같은 의미로 다루지 않는다.

계정 ID·조회 조건·재조회 차수를 요청 키에 포함한다. 조건이 바뀌면 이전 결과를 숨기고 진행 중 요청을 취소한다. 취소 이후 도착한 응답도 반영하지 않는다. `load`와 오류 변환 함수는 모듈 함수 또는 `useCallback`으로 고정한다.

### 건수와 금액

- 응답 전·조회 보류·오류 상태의 전체 건수는 `undefined`다. `총 0건`으로 대체하지 않는다.
- 성공한 빈 목록의 전체 건수는 `0`이며, 이때는 `총 0건`을 표시한다.
- `PaginationSummary`는 건수를 모를 때 건수만 숨기고 페이지당 항목 수 선택은 유지한다.
- 페이지 수 계산용 `?? 0`은 제어용 기본값이다. 이 값을 확인된 전체 건수처럼 표시하지 않는다.
- 커서 API는 전체 건수를 추정하지 않고 지금까지 받은 항목 수만 안내한다.
- 통계의 `IN_PROGRESS`·`null`은 집계 미완료다. 실제 0과 구분하며 임의로 합산하지 않는다.

## 재조회와 기능별 예외

일반 조회의 수동 재시도·필터 변경은 기존 결과를 숨기고 로딩 상태부터 표시한다. 아래 예외는 조회 방식에 필요한 동작이므로 일반 훅으로 억지로 합치지 않는다.

| 훅·기능 | 유지하는 차이 |
| --- | --- |
| `useCampaigns`, `usePointLedger` | 더 불러오기 중 같은 조건의 기존 행을 유지한다. 추가 조회 실패는 기존 행과 함께 오류를 표시하고 같은 커서로 재시도한다. 계정·조건 변경 시 커서와 누적 행을 초기화한다. |
| `useCampaignReports` | 이미 받은 캠페인 실적을 보관하고 새 ID의 실적만 추가 조회한다. 실패한 실적을 0으로 표시하지 않는다. |
| `useAnalyticsQuery` | 같은 계정의 최근 조건을 최대 8개 보관한다. 같은 키의 캐시가 있으면 표시하면서 재검증하며, 다른 조건의 데이터를 대신 표시하지 않는다. |
| `useAdminAccounts` | 공통 조회 위에 403 접근 차단과 Retry-After 대기 정보를 덧붙인다. 내부 실패 정보도 화면에서는 오류로 취급한다. |
| `useTemplateEditor`, `useTemplateChat` | 생성·게시·버전 선택·대화 상태와 서버의 버전 가용성을 함께 관리한다. 주소 변경만으로 대화가 초기화되지 않도록 기존 컴포넌트 식별자를 유지한다. |

조회와 생성·수정·삭제는 구분한다. 변경 요청은 기능별 제출 잠금과 오류 안내를 유지하고, 조회 훅의 재시도를 이유로 변경 요청을 자동 반복하지 않는다.

## 서로 다른 로딩 단계

1. 인증 복원 중: `AdminAuthProvider`가 로그인 확인 화면을 표시한다.
2. 페이지 코드 로딩 중: `AdminLayout`의 `Suspense`가 본문 로딩 안내를 표시한다.
3. 페이지 코드·렌더링 실패: `AdminPageErrorBoundary`가 본문 오류와 새로고침을 제공한다.
4. API 데이터 조회 중: 각 조회 화면이 공통 테이블·카드 상태를 표시한다.

코드 로딩 실패를 API 재시도로 복구하려 하지 않는다. 인증 저장소 장애를 데이터 없음으로 표현하거나, 데이터 조회 실패만으로 직접 로그아웃 처리하지 않는다.

## 화면 점검 결과

| 화면 | 조회·초기 상태 처리 |
| --- | --- |
| 관리자 계정 | 공통 조회 + 권한·대기시간 래퍼. 로딩·오류 이후에만 빈 결과·전체 건수 표시. |
| 점주·사용자 목록 | 공통 조회, URL 조건, 테이블 로딩·오류·빈 결과. 응답 전 전체 건수 숨김. |
| 무효노출·캠페인 경고 | 공통 조회와 기간·ID 검증. 유효하지 않은 조건은 요청하지 않고, 오류를 0건으로 표시하지 않음. |
| 결제·환불·정산 불일치·정책 이력 | 일반/결제 조회 래퍼와 공통 테이블 상태. 응답 전 전체 건수 숨김. |
| 현재 충전 정책 | 로딩 안내 → 공통 오류/재시도 → 현재·예약 정책 표시. |
| 포인트 기간 합계 | 공통 조회로 통합. 점주·기간 미입력은 조회 보류, 계정·조건별로 응답 구분. |
| 포인트 변동 내역 | 계정별 커서 조회. 최초 로딩과 추가 로딩을 구분하고 추가 조회 오류에도 기존 행 유지. |
| 매출·대시보드 통계 | 통계 조회 훅. 조회 실패·집계 미완료·실제 0을 구분. |
| 캠페인 목록·실적·상세 | 커서 목록과 실적 추가 조회를 구분. 상세는 공통 조회 상태 사용. |
| 템플릿 목록·편집 | 공유 목록과 기능별 편집 훅 유지. 목록의 로딩·오류·빈 결과와 편집의 초기 상세 로딩을 구분. |

## 새 화면·변경 작업의 확인 항목

- 필수 조건이 없을 때 요청하지 않는가?
- 첫 응답 전에 빈 결과·0건·0원을 보여주지 않는가?
- 검색·정렬·페이지 조건이 URL과 일치하며 뒤로 가기로 복원되는가?
- 계정·조건 변경 직후 이전 데이터와 커서가 숨겨지는가?
- 늦은 응답이 현재 화면을 덮지 않는가?
- 최초 실패와 더 불러오기 실패를 구분하고 수동 재시도로 복구되는가?
- 성공한 빈 결과에는 빈 상태와 실제 0건을 표시하는가?

검증 시 응답을 지연하거나 실패시키고, 필터·계정·페이지를 전환한다. 필요한 동작 차이는 이 문서에 근거를 남기고 유지한다.
