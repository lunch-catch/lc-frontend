# 관리자 성능 측정과 개선

## 측정 조건

- 비교 기준: develop의 b32c0af9, 개선 브랜치: perf/admin-runtime-optimization.
- 개발 서버가 아닌 Vite 프로덕션 빌드, Windows Chrome, 로컬 백엔드의 실제 관리자 인증을 사용했다.
- Lighthouse 13.5.0: 데스크톱 1440×1100, RTT 40ms, 10Mbps, CPU 배율 1. 로그인은 비로그인 상태, 나머지는 로그인 상태에서 측정했다.
- 목록 테스트: 1440×1000, CPU 4배 지연. 캠페인 50건씩 500건, 미리보기는 실제 템플릿을 복제한 100건의 고정 응답을 사용했다. 실제 DB에 가짜 데이터를 추가하지 않았다.
- 점수와 시간은 이 조건의 실험값이며 배포 서버, 네트워크, 데이터, Chrome 버전에 따라 달라진다. 모바일·배포 주소에서의 100점을 보장하는 수치는 아니다.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |

그래프 시간은 CPU 4배 지연 상태에서 같은 경로를 3회 이동한 중앙값이다. 호버 중 정적 SVG의 DOM 변경도 454회에서 0회로 줄었다. 목록 스크롤은 페이지 대신 표 내부가 스크롤되는 좁은 화면에서도 실제 스크롤 컨테이너를 대상으로 측정했다. 이 값은 빠르게 긴 구간을 건너뛰는 부하 실험이며 평상시 프레임 속도와 같지 않다.

## 변경 내용과 범위

### 조회 결과 재사용

useApiResource는 로그인 세션의 인증 객체·조회 함수·조건별 성공 응답을 30초 동안 최대 32건 보관한다. 탭 재진입은 유효한 캐시를 즉시 사용하고, 만료된 조회는 다시 요청한다. 오류는 저장하지 않으며 권한 오류를 값으로 감싸는 관리자 계정 조회는 캐시에서 제외한다.

변경 후 refresh는 같은 조회 함수의 검색 조건·페이지 캐시를 모두 비운다. 무효화 전에 시작한 요청이 늦게 끝나도 캐시를 되살리지 않는다. 데이터는 메모리에만 보관한다. 자동 폴링이나 브라우저 포커스 재조회는 추가하지 않았다. 상세 계약은 [상태 관리 규칙](state-management.md)을 따른다.

### 그래프 호버

좌표와 축 계산은 데이터·크기에 따라 메모하고, 정적인 SVG 축·도형은 DashboardChartPlot으로 분리했다. 마우스 이동은 프레임당 한 번 처리한다. 같은 날짜 안에서 세로로 이동할 때에는 툴팁 요소의 위치만 갱신한다. 부모에 CSS 변수를 반복해서 설정해 SVG 전체 스타일을 다시 계산하지 않는다. 키보드 포커스와 날짜별 보조 지표는 유지한다.

### 미리보기 수명

TemplateThumbnail은 화면과 위아래 300px 이내에서만 iframe을 유지한다. 멀어진 미리보기의 iframe, HTML 파싱 결과, ResizeObserver를 해제하고 A4 공간은 유지한다. 다시 접근하면 미리보기를 만든다. 메모리 압박을 줄이는 대신 되돌아올 때 문서를 다시 생성하는 비용이 있다.

### 커서 목록 가상화

캠페인과 포인트 변동 내역은 100행까지 기존 방식으로 표시한다. 초과하면 @tanstack/react-virtual로 보이는 행과 주변 4행씩만 렌더링한다. 받은 데이터나 커서를 잘라내지 않는다.

VirtualTableRows는 한 줄짜리 고정 높이 행(40·48·56px)을 위한 관리자 전용 구성이다. 테이블 내부 스크롤과 페이지 스크롤, 열 숨김·순서 변경을 지원한다. 여러 줄·가변 높이 행에는 그대로 적용하지 않는다. 작은 페이지네이션 목록은 가상화하지 않는다. 가상화 의존성은 실제 사용하는 목록에서 직접 import해 일반 테이블 진입 시 포함되지 않게 했다.

### 초기 표시와 접근성

현재 주소의 페이지 코드 다운로드를 인증 복원과 병렬로 시작한다. 데이터 요청과 화면 접근은 기존 인증 가드 이후에 실행한다. 폰트 CSS는 비동기로 읽고, 메타 설명과 유효한 robots.txt를 제공한다. 관리자 라이트 모드의 텍스트·버튼·테이블 헤더 대비를 보정한다. 공통 SelectField와 DateRangePicker의 접근성 이름에는 보이는 선택값도 포함한다.

## 재검증

루트에서 다음 명령을 실행한다.

```bash
pnpm --filter admin test
pnpm --filter admin lint
pnpm --filter admin build
pnpm --filter @repo/ui typecheck
pnpm --filter @repo/ui lint
```

- 캐시: 같은 탭을 30초 이내 재방문하고 Network에서 추가 요청과 로딩 표시가 없는지 확인한다. 30초 후 재진입·수동 재시도·변경 작업 후에는 다시 요청해야 한다. 로그아웃 후 다른 계정으로 들어오면 이전 결과가 보이면 안 된다.
- 미리보기: 많은 템플릿을 끝까지 스크롤하며 DevTools에서 iframe 수가 누적되지 않는지 확인한다. 돌아오면 미리보기가 다시 나타나고 카드 높이가 바뀌지 않아야 한다.
- 목록: 500건을 불러와 처음·마지막 행, 행 높이 세 종류, 열 숨김·재배치, 가로 스크롤, 키보드 상세 열기를 확인한다. DOM 행 수는 전체 건수보다 작아도 모든 데이터에 접근할 수 있어야 한다.
- 그래프: 마우스·키보드 포커스, 음수·미확정 구간, 비교 기간과 보조 지표를 확인한다. Lighthouse의 단일 점수와 별도로 실제 조작 비용을 측정한다.
- Lighthouse: 프로덕션 빌드를 제공하고 로그인 상태와 도착 URL을 확인한 후 페이지별로 측정한다. 로그인 화면으로 리다이렉트된 보고서를 보호된 페이지의 결과로 사용하지 않는다. 로컬 인증의 분당 요청 제한에 걸리면 Retry-After 이후 재측정한다.

로그인 첫 방문의 인증 복원 요청은 쿠키가 없으면 정상적으로 401을 반환한다. Lighthouse는 이를 콘솔 네트워크 오류로 집계하므로 Best Practices 점수에 남는다. 점수를 위해 인증 검사를 생략하거나 실패를 숨기지 않았다.
